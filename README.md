# Desktop TCP Signal Monitor — Autotest Project

Тестовый проект для проверки десктоп-приложения, входящего в состав распределённой системы управления. Приложение отображает значения сигналов, полученных от удалённого сервиса через TCP-сокет. В рамках проекта реализован симулятор TCP-сервера и автотесты на pytest для самого критичного сценария — обрыва связи во время сессии.

---


## Описание исходной задачи

**Исходные данные.** Десктоп-приложение — часть распределённой системы управления. Приложение отображает значения сигналов, полученных от удалённого сервиса через TCP-сокет.

**Главное окно содержит:**
- Таблицу сигналов (ID, имя, значение, качество, время)
- Кнопку «Подключиться» для установки соединения с сервисом
- Кнопку «Обновить» для ручного запроса значений

**Сервис-симулятор (отдельный процесс):**
- Отправляет 10 сигналов с изменяющимися значениями (синусоида / случайные)
- Работает на порту 2001

**Задача:**
1. Составить чек-лист для проверки приложения (не более 15 пунктов)
2. Выбрать самый критичный сценарий из чек-листа и написать автотест на Python (pytest)

## Чек-лист (15 пунктов)

| №  | Пункт | Тип | Приоритет | Что проверяем |
|----|-------|-----|-----------|---------------|
| 1  | Запуск приложения | Позитивный | P0 | Приложение открывается, главное окно отображается, таблица сигналов пустая, кнопки «Подключиться» и «Обновить» активны/неактивны согласно логике |
| 2  | Установка TCP-соединения | Позитивный | P0 | Нажатие «Подключиться» при запущенном симуляторе на порту 2001 → соединение устанавливается, кнопка меняет состояние, статус — «Подключено» |
| 3  | Отображение всех 10 сигналов | Позитивный | P0 | После подключения в таблице ровно 10 строк, у каждой заполнены ID, имя, значение, качество, время |
| 4  | Обновление значений в реальном времени | Позитивный | P0 | Значения сигналов меняются (синусоида/случайные), время обновляется, таблица перерисовывается без мерцания |
| 5  | Ручное обновление по кнопке «Обновить» | Позитивный | P1 | Нажатие «Обновить» → значения и время обновляются, запрос уходит на сервис, старые значения заменяются новыми |
| 6  | Корректность полей таблицы | Позитивный | P1 | ID — уникальны, имя — не пустое, значение — соответствует типу (число), качество — одно из допустимых, время — валидное |
| 7  | Повторное подключение после обрыва | Позитивный | P0 | Выключить симулятор → приложение показывает ошибку/статус «Отключено» → включить симулятор → нажать «Подключиться» → соединение восстанавливается |
| 8  | Подключение при недоступном сервисе | Негативный | P0 | Симулятор не запущен → нажать «Подключиться» → появляется сообщение об ошибке, приложение не зависает, кнопка снова активна |
| 9  | Поведение при обрыве связи во время сессии | Негативный | P0 | Во время работы выключить симулятор → приложение не падает, показывает статус «Отключено»/ошибку, данные не «замерзают» молча |
| 10 | Повторное нажатие «Подключиться» | Негативный | P1 | Двойное нажатие кнопки не создаёт два соединения, не вызывает дублирование данных, кнопка блокируется на время подключения |
| 11 | Спам кнопки «Обновить» | Негативный | P2 | Многократное нажатие «Обновить» подряд не приводит к зависанию, дублированию строк или утечке памяти |
| 12 | Некорректный порт в настройках | Негативный | P1 | Указать порт 2002 (закрытый) → нажать «Подключиться» → ошибка, приложение не падает; вернуть 2001 → подключение работает |
| 13 | Поведение при закрытии приложения | Позитивный | P1 | При закрытии окна TCP-соединение корректно разрывается, процесс завершается без ошибок, порт освобождается |
| 14 | Реакция на некорректные данные от сервиса | Негативный | P2 | Симулятор отправляет значение неверного типа (строка вместо числа) или пустое имя → приложение не падает, отображает заглушку/ошибку |
| 15 | Производительность при быстром потоке данных | Позитивный/Негативный | P2 | При частом обновлении значений (например, 10 раз/сек) приложение не тормозит, UI не «залипает», память не растёт бесконтрольно |

### Как использовать чек-лист

- **P0** — проходить при каждом релизе, блокирует релиз при провале.
- **P1** — проходить перед релизом, при нехватке времени — по остаточному принципу.
- **P2** — проходить периодически или при изменениях в соответствующем модуле.

## Самый критичный пункт чек-листа

**Пункт 9 — Поведение при обрыве связи во время сессии.**

Это самый критичный пункт для десктоп-приложения, работающего с удалённым сервисом через TCP. Обрыв связи — типичный сценарий в реальных условиях (проблемы сети, перезагрузка сервиса, обрыв кабеля), и поведение приложения в этот момент напрямую влияет на безопасность оператора: если приложение молча показывает устаревшие данные, оператор может принять неверное решение.

### Что должно происходить при обрыве связи

**Правильное поведение:**
1. Приложение сразу обнаруживает разрыв (в течение 1–3 секунд).
2. В UI появляется явное сообщение: «Соединение потеряно» или статус «Отключено».
3. Кнопка «Подключиться» снова активна для повторного подключения.
4. Данные в таблице помечаются как устаревшие (например, серым цветом или с пометкой «нет связи»).
5. Приложение не падает и не зависает.
6. Если предусмотрено — запускается автоматическое переподключение с интервалом.

**Неправильное поведение (баг):**
1. Приложение молча продолжает показывать старые значения.
2. UI зависает, кнопки не нажимаются.
3. Приложение падает с ошибкой.
4. Оператор не понимает, что данные неактуальны.

| Тест | Сценарий | Чек-лист |
|------|----------|----------|
| `test_connect_and_receive_signals` | Подключение к серверу, приём 10 сигналов, проверка структуры каждого сигнала | Пункты 2, 3, 6 |

## Установка и запуск

### Требования

- Python 3.10+
- Windows / Linux / macOS

### Шаг 1. Клонирование репозитория

```bash
git clone https://github.com/<ваш-username>/desktop_tcp_test.git
cd desktop_tcp_test
```

### Шаг 2. Создание виртуального окружения

**Windows (PowerShell):**
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

> Если PowerShell выдаёт ошибку о подписи скрипта:
> ```powershell
> Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser -Force
> .\.venv\Scripts\Activate.ps1
> ```

**Linux / macOS:**
```bash
python3 -m venv .venv
source .venv/bin/activate
```

### Шаг 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

### Шаг 4. Запуск тестов

```bash
pytest
```

Или с подробным выводом:

```bash
pytest -v
```

## Описание компонентов

### `server/signal_server.py`

Симулятор TCP-сервера. Слушает порт 2001, принимает подключение клиента и отправляет 10 сигналов каждые 500 мс в формате JSON-строк, разделённых символом новой строки (`\n`). Часть сигналов — синусоида (чётные ID), часть — случайные значения (нечётные ID).

Каждый сигнал содержит:
```json
{
  "id": 1,
  "name": "Signal_1",
  "value": 45.23,
  "quality": "Good",
  "timestamp": 1727612345.67
}
```

### `conftest.py`

Общие фикстуры pytest. Фикстура `signal_server` запускает TCP-сервер перед каждым тестом и останавливает после. Область видимости — `function`, чтобы каждый тест работал с чистым сервером.

### `tests/test_connection_break.py`

Тестовый клиент `SignalClient` имитирует поведение десктоп-приложения: подключается к серверу, принимает сигналы, обнаруживает обрыв. Три теста покрывают подключение, обрыв связи и повторное подключение.
